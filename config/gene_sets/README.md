# Pre-registered gene sets

These sets are **frozen before outcome analysis** (see `docs/adr/0003-preregistration.md`). Each
build writes a SHA-256 to `results/geneset_lock.json`; changing a set after data lock breaks the
hash and is flagged by CI.

| File | Role | How built |
|---|---|---|
| `circadian_core.tsv` | **Primary** hypothesis test set (~23 core TTFL genes) | Hand-curated, symbols validated against MAGMA `.gene.loc` at build time |
| `circadian_extended_GO0007623.tsv` | **Sensitivity** set (GO:0007623 "circadian rhythm") | Generated by `epicirc.geneset.curate` from a pinned GO release; not hand-edited |
| `positive_control.tsv` | **Positive control** (known epilepsy genes) | Must show enrichment or the wiring is broken |
| negative controls | **Null calibration** | `epicirc.geneset.curate` draws N=1000 random gene sets **size- and gene-length-matched** to the core set (fixed seed) — MAGMA's competitive test already conditions on gene length, so matching guards against residual bias |

## Why a curated core set *and* controls

The single biggest researcher-degree-of-freedom risk in "clock gene" studies is picking the gene
list post hoc. We defend against this three ways: (1) a small, mechanistically-justified core set
fixed in advance; (2) a GO-defined extended set built by script (no hand-picking); (3) empirical
null calibration from matched random sets so the reported enrichment p-value is interpretable
against the pipeline's own false-positive rate.

## Overlap audit
`curate` reports overlap between the circadian sets and (a) the positive-control epilepsy set and
(b) genome-wide significant ILAE loci, so any enrichment driven by a gene that is *both* a clock
gene and an established epilepsy gene (e.g. via pleiotropy) is transparent, not hidden.
